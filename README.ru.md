## 🚀 Быстрая установка (Ubuntu 20.04 / 22.04 / 24.04)

Для автоматической установки на чистый Linux-сервер выполните:

```bash
wget -qO- https://raw.githubusercontent.com/fenjo26/Orbitra.link/main/install.sh | bash
```

Установщик автоматически:
- Скачивает исходный код с GitHub
- Устанавливает Nginx, PHP 8.0+ (FPM), SQLite3 и Node.js 20
- Собирает и разворачивает фронтенд на React/Vite
- Настраивает SSL-сертификат Let's Encrypt для вашего домена

## 🖥 Системные требования

Orbitra намеренно лёгкая — она работает на связке **PHP + SQLite** за Nginx, без тяжёлых фреймворков и **без отдельного сервера БД** (нет ClickHouse, Redis или MySQL). Благодаря этому ей нужно намного меньше RAM, чем трекерам на ClickHouse, и она комфортно помещается на самых дешёвых VPS.

### Базовая конфигурация (обязательная)

- **CPU:** 1 vCPU (x86_64)
- **RAM:** 1 ГБ (рекомендуется 2 ГБ)
- **Диск:** 20 ГБ SSD
- **ОС:** Ubuntu 20.04 / 22.04 / 24.04 или Debian 11 / 12
- Чистый сервер, без панели управления; доступ root/sudo

### Подбор ресурсов под трафик (ориентир)

| Кликов в день | RAM | CPU | Диск |
|---|---|---|---|
| до ~100 000 | 1–2 ГБ | 1–2 vCPU | 20 ГБ SSD |
| ~100 000 – 500 000 | 2–4 ГБ | 2 vCPU | 40 ГБ SSD |
| ~500 000 – 1 000 000 | 4–8 ГБ | 4 vCPU | 80 ГБ SSD |

> ✅ **Проверено на практике:** Orbitra хорошо работает на VPS **2 vCPU / 2 ГБ RAM / 20 ГБ SSD** (Ubuntu 24.04) на небольшом трафике — удобная и недорогая точка старта. Более высокие строки таблицы — запас на тяжёлый трафик, а не жёсткое требование.

**ПО (устанавливается автоматически через `install.sh`):** Nginx, PHP 8.0+ с FPM (`php-sqlite3`, `php-curl`, `php-mbstring`, `php-xml`, `php-zip`), SQLite 3, Node.js 20 (только для сборки), Certbot для SSL.

> 💡 **Почему требования ниже, чем у Keitaro?** Keitaro хранит клики в ClickHouse + Redis + MySQL, поэтому его требования к RAM растут очень быстро (до 64 ГБ при миллионах кликов в день). Orbitra держит всё в одном файле SQLite, поэтому узкое место — не RAM, а дисковый I/O и модель одного писателя SQLite. SQLite (в режиме WAL) уверенно тянет низкие и средние объёмы; для устойчивых **миллионов кликов в день** с тяжёлой аналитикой архитектурно лучше подходит трекер на колоночной БД, например Keitaro.

> 💡 **Про тариф на 1 ГБ:** самому трекеру нужно очень мало памяти, но установщик собирает фронтенд на сервере через Vite — это самый прожорливый по памяти шаг. На машине с 1 ГБ добавьте ~1–2 ГБ swap перед установкой (или собирайте фронтенд отдельно), чтобы сборке хватило памяти. Диск расходуется скромно — он растёт в основном за счёт логов кликов/конверсий в SQLite со временем.

## ✨ Ключевые возможности

### 1. **Полная совместимость с Keitaro**
- **Click API с токенами** — полная совместимость с существующими интеграционными скриптами
- **Импорт из Keitaro** — перенос кампаний, офферов, доменов и потоков с сохранением токенов
- **Совместимость по API** — работает с существующими постбеками и вебхуками

### 2. **Современная архитектура**
- **Бэкенд**: PHP 8.3+ без тяжёлых фреймворков (чистый код)
- **База данных**: SQLite 3 (один файл, автоматическое создание схемы)
- **Фронтенд**: React 19 + Vite 7 + Tailwind CSS 4
- **UI/UX**: современный дизайн с несколькими встроенными темами (светлая, тёмная, зелёная, неон) и кастомной палитрой

### 3. **Управление кампаниями**
- **6 моделей выплат**: CPC, CPuC, CPM, CPA, CPS, RevShare
- **30+ параметров**: keyword, sub_id_1...30, cost, creative_id и другие
- **Продвинутая логика потоков**: Intercept → Regular → Fallback с весами и позициями
- **Гибкая фильтрация**: GEO, устройство, ОС, браузер, ISP, IP, язык, реферер
- **A/B-тесты**: встроенный сплит-тест с взвешенной ротацией

### 4. **Интеграции**
- **S2S-постбеки** — Server-to-Server постбеки от партнёрских сетей
- **Шаблоны партнёрок**: уровня платформ (Everflow, CAKE, HitPath, Affise, TUNE/HasOffers), а также сети Leadbit, M4Leads, Dr.Cash, AdCombo и другие
- **Шаблоны источников**: Facebook, Google, TikTok, Yandex, Taboola, Outbrain, Email и другие
- **Click API** — токены для работы с интеграционными скриптами
- **Telegram-бот** — мониторинг и уведомления в реальном времени

### 5. **Аналитика и отчёты**
- **Дашборд** — сводная статистика по кликам, конверсиям и доходу
- **Тренды** — детальная аналитика с графиками по 8 метрикам
- **Отчёты по кампаниям** — группировка отчётов по любому параметру
- **Лог конверсий** — детальный лог конверсий с фильтрами
- **Симуляция трафика** — симуляция кликов для тестирования потоков

### 6. **Мультиязычность**
- **7 языков**: 🇬🇧 английский, 🇷🇺 русский, 🇺🇦 украинский, 🇪🇸 испанский, 🇨🇳 китайский (упрощённый), 🇫🇷 французский, 🇩🇪 немецкий
- **Полное покрытие i18n** — локализован каждый элемент интерфейса, 100% паритет ключей во всех локалях
- **Переключение языка** — в настройках профиля, без перезагрузки страницы

### 7. **Telegram-бот**
- **10+ команд**: `/stats`, `/campaigns`, `/top`, `/conversions` и другие
- **Уведомления**: моментальные уведомления о конверсиях
- **Ежедневная сводка**: автоматический отчёт по кампаниям
- **Мультиязычность**: бот говорит на всех 7 языках интерфейса (EN, RU, UK, ES, ZH, FR, DE) через `/lang`

### 8. **Управление доменами**
- **Проверка DNS** — автоматическая проверка A-записи
- **HTTPS-only** — принудительный редирект на HTTPS
- **Защита от ботов** — перехват `/robots.txt` и `X-Robots-Tag`
- **Режим парковки** — парковка домена с защитой

### 9. **Миграция из Keitaro**
- **Полный перенос данных**: кампании, офферы, домены, потоки, партнёрские сети, источники, лендинги
- **Сохранение токенов** — токены Click API переносятся для совместимости
- **Гайд внутри UI** — пошаговая инструкция по созданию бэкапа Keitaro
- **Режим предпросмотра** — предпросмотр перед реальным импортом

### 10. **Anti-Bot Challenge**
- **Проверка на человека для каждой кампании** — не даёт корпоративным email-краулерам и кликботам засорять статистику
- **reCAPTCHA v2** — классический чекбокс «Я не робот»
- **reCAPTCHA v3** — невидимая, на основе score с настраиваемым порогом
- **Кастомный код** — вставьте любой HTML/JS-виджет проверки
- **Чистая статистика** — клики логируются только после успешной проверки, поэтому боты не попадают в отчёты; состояние проверки подписывается (HMAC-SHA256) и истекает через 15 минут для защиты от replay

## 🤖 Интеграция с нейросетями (MCP)

Начиная с версии 0.9.5.0 к Orbitra можно подключить ИИ-ассистента (Claude Desktop и другие MCP-клиенты) через **MCP-сервер** в папке [`mcp/`](mcp/README.md). После подключения трекером можно управлять на обычном языке:

> «Как отработали кампании за последние 7 дней?»
> «Создай 10 кампаний под оффер №4 — по одной на GEO: US, CA, GB, DE, FR.»
> «Добавь домен track.example.com и повесь на его корень кампанию 12.»

- **31 инструмент**: чтение (метрики, кампании, конверсии, отчёты) и управление (создание/массовое создание/редактирование/удаление кампаний, офферов, доменов, источников, лендингов).
- **API-ключи с областями прав**: `read` (только аналитика) и `write` (управление). Генерируются в **Пользователи → API-ключи**.
- **Безопасно**: ключ уходит только на ваш адрес, read-ключи физически не могут менять данные.

Подробнее — [docs/mcp.md](docs/mcp.md) и [mcp/README.md](mcp/README.md).

## 🔐 Первый вход и настройка

В Orbitra **нет** аккаунта по умолчанию (`admin`/`admin`) — учётные данные администратора вы задаёте сами при первом запуске.

Когда вы впервые открываете админ-панель (`/admin.php`), система обнаруживает, что пользователей ещё нет, и запускает **мастер первичной настройки**. В нём вы создаёте своего администратора:

- **Имя пользователя** — минимум 3 символа
- **Пароль** — минимум 6 символов (с подтверждением)
- **Часовой пояс** и **язык интерфейса** (один из 7 языков)

После создания администратора мастер больше не появляется, и вы входите с заданными логином и паролем.

## 🔄 Импорт из Keitaro

### Подготовка дампа Keitaro

На сервере Keitaro выполните:

```bash
# Подключиться к серверу Keitaro
ssh root@YOUR_KEITARO_SERVER_IP

# Создать дамп
bash -lc '
source /etc/keitaro/env/inventory.env

cat > /root/keitaro-mariadb.cnf <<EOF
[client]
user=$MARIADB_KEITARO_USER
password=$MARIADB_KEITARO_PASSWORD
host=127.0.0.1
port=3306
protocol=tcp
EOF
chmod 600 /root/keitaro-mariadb.cnf

TABLES="keitaro_affiliate_networks keitaro_groups keitaro_offers keitaro_domains keitaro_campaigns keitaro_campaign_postbacks keitaro_landings keitaro_streams keitaro_stream_filters keitaro_stream_offer_associations keitaro_stream_landing_associations keitaro_traffic_sources keitaro_ref_sources"

mysqldump --defaults-extra-file=/root/keitaro-mariadb.cnf \
  --single-transaction --quick --skip-lock-tables \
  "$MARIADB_KEITARO_DATABASE" $TABLES \
  | gzip > /root/keitaro_orbitra_full.sql.gz

ls -lah /root/keitaro_orbitra_full.sql.gz
'

# Скачать файл
scp root@YOUR_KEITARO_SERVER_IP:/root/keitaro_orbitra_full.sql.gz .
```

### Импорт в Orbitra

1. Откройте **Миграции** в меню админки
2. Следуйте инструкции в блоке «Как создать бэкап Keitaro»
3. Загрузите файл `keitaro_orbitra_full.sql.gz`
4. Выберите, что импортировать (кампании, офферы, домены и т. д.)
5. Нажмите «Показать предпросмотр» для проверки
6. Нажмите «Импортировать в Orbitra» для реального импорта

### Исправлено
- 🔄 **Обновление из админки само восстанавливается после незавершённого Git-конфликта.**
  Перед загрузкой релиза обновлятор напрямую проверяет состояние `unmerged files`,
  отменяет зависший merge/rebase и очищает рабочее дерево. Если локальные правки из
  stash конфликтуют с новой версией, они остаются сохранены в Git stash, а частично
  применённый конфликт сразу убирается — следующее обновление снова работает.

- 🗜 **Архив, который PHP не умеет распаковать, выглядел как проблема с правами.** Пресет «максимальное сжатие» в 7-Zip и WinRAR пишет записи методом LZMA, BZip2 или PPMd, а libzip обычно собран только со Store и Deflate — архив при этом открывается и список файлов читается, падает только распаковка. Теперь при неудачной распаковке проверяется метод сжатия каждой записи, и если он не поддерживается — панель называет его и просит пересобрать ZIP с Deflate.
- 🔗 **Полу-цепочка сертификата показывалась как установленная.** `fullchain.pem`, в котором лежит только leaf без промежуточного сертификата, открывается в Firefox (он сам подтягивает intermediate из своего хранилища), но падает в Chrome и curl с *unable to get local issuer certificate*. Теперь `core/ssl_manager.php` на каждом проходе считает сертификаты в цепочке и помечает домен `failed` с причиной `incomplete_chain`, если их меньше двух — и сразу после выпуска, и позже, чтобы поймать файл, который испортился уже после успешного выпуска.
- 🌐 **Серверные сообщения об ошибках были жёстко по-русски.** `upload_landing` и SSL-воркер возвращали целые предложения по-русски; в панели с семью локалями строка бэкенда, которую фронтенд не может перевести, — это баг. Теперь бэкенд отдаёт машинные коды плюс объект `detail` с измеренными фактами, а фронтенд формулирует их для каждой локали; собственный вывод Certbot проходит как диагностический текст без перевода.

Теперь конфиг всегда начинается с блока `listen 80 default_server; server_name _;` — доступ по IP заложен в структуру, а не получается случайно, — а сертификаты выписываются через `certbot certonly --webroot`, который к Nginx не прикасается. HTTPS-блоки Orbitra пишет сама, как и раньше.

- 🤖 **Мультиязычный Telegram-бот** — бот теперь говорит на всех 7 языках интерфейса (🇬🇧 EN, 🇷🇺 RU, 🇺🇦 UK, 🇪🇸 ES, 🇨🇳 ZH, 🇫🇷 FR, 🇩🇪 DE). Переключение через `/lang en|ru|uk|es|zh|fr|de`.

### Документация
- 🖥 Добавлен раздел **Системные требования** (комфортно работает на 1 vCPU / 1 ГБ RAM / 20 ГБ SSD).
- 📚 Документация обновлена под текущую версию и набор функций.
