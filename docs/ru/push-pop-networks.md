# Push и pop сети

Импорт расхода из рекламных сетей push/pop-трафика плюс **Zone Killer** — правила, которые находят (а с вашего разрешения и блокируют) зоны, сжигающие деньги. Всё в одном месте: карточка **Push/Pop сети** в **⚙ → Интеграции**, в группе рекламных сетей рядом с Facebook / TikTok / Google.

## Сети

| Сеть | Уровень расхода | API-ключ |
|---|---|---|
| **AdMaven** | кампания × зона | Рекламный кабинет → раздел API → API token |
| **PropellerAds** | кампания × зона | SSP → Profile → API token |
| **Kadam** | кампания × зона | Рекламный кабинет → раздел API → API token |
| **Galaxion** | кампания × зона | E-mail и пароль аккаунта (трекер сам получит токен) или готовый API-токен |
| **HilltopAds** | только кампания | My Account → вкладка API → API key |
| **Adsterra** | только кампания | Settings → API → Generate new token (работает только последний созданный токен) |
| **Clickadu** | только кампания | Рекламный кабинет → раздел API → API key |

У сетей с пометкой «только кампания» разбивка по зонам в API есть, но её строки не несут id кампании — зону там нельзя привязать к кампании, чьи клики она купила. Их расход распределяется по кликам кампании, и карточка подключения честно предупреждает об этом заранее.

## Подключение

Выберите плитку сети, вставьте ключ, нажмите **Проверить подключение** — она показывает реальный баланс аккаунта, — и сохраните. У каждого подключения свой интервал обновления; кнопки в списке: **Обновить расход** (сейчас), пауза, изменить, удалить. Уже импортированный расход после удаления остаётся в отчётах.

Синхронизация идёт в том же проходе `aggregator_cron.php`, что и остальные расходные подключения (см. [Расходы](costs.md#cron)): каждый проход перечитывает последние 5 дней, первый — 30. Повторная синхронизация дня безопасна: расход пересчитывается, а не накапливается.

## Как расход попадает на клик

**Главное требование** то же, что для Facebook или TikTok: кампания должна использовать шаблон источника этой сети, чтобы ссылка передавала id кампании сети (в `ad_campaign_id`) и id зоны (шаблоны Keitaro пишут его в `source`, встроенный шаблон PropellerAds — в `zone`). Без макроса зоны расход всё равно придёт — но только на уровень кампании, без разбивки по зонам.

Матчинг от самого специфичного уровня к самому широкому:

1. **кампания × зона** — строка зоны относится только к кликам того же дня, несущим **оба** id: и зоны, и кампании сети. Голого id зоны мало: id зон не уникальны между сетями.
2. **кампания** — строка зоны, чья зона не нашла кликов, суммируется на клики кампании без зоны (и никогда не залезает на клики, уже оценённые их собственными зонами, — несколько непривязавшихся зон складываются, а не затирают друг друга).

Ключи параметров клика, которые считаются зоной: `zone`, `zone_id`, `zoneid`, `sub_source_id`.

Если синхронизация отвечает «записей получено, но ни одна не легла на клики» — скорее всего, кампания не использует шаблон источника этой сети: ссылке не с чем матчиться. Диагностика «Получено N, сопоставлено 0» из [Расходов](costs.md) применима и здесь.

## Zone Killer

Карточка на вкладке **Общие** редактора кампании (кампания должна быть сохранена). Правило привязывает кампанию к одному push/pop-подключению и решает, какие зоны — кандидаты:

- **окно** — сколько дней назад смотреть (расход и конверсии суммируются по зоне за окно);
- **мин. расход** — зона, потратившая меньше, не стоит внимания;
- **ноль конверсий** и/или **макс. ROI** — условия блокировки;
- **режим** — `dry_run` (по умолчанию) или `auto` с лимитом блокировок за проход.

Кандидаты считаются по `clicks.cost` / `clicks.revenue` в разрезе зоны — по тем же распределённым числам, что показывают отчёты, и по тем же ключам зон, по которым матчился импорт расхода, поэтому правило не может осудить зону, которую импорт оценил иначе.

- **Dry-run** показывает список кандидатов; вы выбираете и жмёте **Заблокировать выбранное**.
- **Auto** позволяет `zone_rules_cron.php` исполнять кандидатов самому (с лимитом за проход) и присылать Telegram-уведомление о заблокированном.

Блокировка идёт через write-API сети для **AdMaven, HilltopAds, PropellerAds, Kadam и Galaxion**. У **Adsterra и Clickadu** пригодного zone write-API нет: их правила остаются в dry-run, а карточка копирует выбранные id зон, чтобы вставить их в блэклист сети вручную.

Каждая блокировка и разблокировка — ручная или автоматическая — попадает в журнал (только добавление, с метриками, стоявшими за решением); текущий набор блоков — это зоны, чьё последнее успешное действие «блок». Журнал показывается под правилом.

> Для сетей «только кампания» (HilltopAds, Adsterra, Clickadu) Zone Killer судит зоны приблизительно — по их доле кликов кампании, потому что API не даёт расход по зонам. Держите их правила в dry-run и просматривайте список перед блокировкой.

## Крон

```
*/15 * * * * php /var/www/orbitra/aggregator_cron.php >> /var/www/orbitra/var/logs/aggregator.log 2>&1
*/30 * * * * php /var/www/orbitra/zone_rules_cron.php  >> /var/www/orbitra/var/logs/zone_rules.log 2>&1
```

Первая строка — крон, который установщик добавляет для синхронизации расходов. Вторую — исполнитель Zone Killer — добавьте сами, и только если используете режим `auto`; проход дешёвый (правило без кандидатов — один GROUP BY по кликам кампании). Флаги: `--campaign=12` (одна кампания), `--quiet`.
