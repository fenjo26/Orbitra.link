# Проверки ссылок

**Проверки ссылок** открывают ваши офферы и домены по расписанию, проходят редиректы и сообщают, когда что-то перестаёт работать: оффер выключили, трекер отвечает 404, редирект ведёт на другой домен, домен умер.

По умолчанию выключено: каждая проверка ссылки оффера — это клик в статистике партнёрки, поэтому обновление само их не начинает. Включается в **Интеграции → Проверки ссылок**.

## Где что находится

| Что | Где |
|---|---|
| Настройка: вкл/выкл, что проверять, интервал, прокси, воркер | Интеграции → **Проверки ссылок** |
| Список: что сломано и почему, цепочка редиректов, история | Уведомления → **Проверки** |
| Сколько ссылок требуют внимания | Индикатор в верхней панели (красный, когда есть проблемы) и число рядом с «Уведомлениями» |
| Сломанный оффер или домен | Красная метка рядом с названием на страницах **Офферы** и **Домены**; клик открывает ссылку в «Проверках» |
| Сводка | Полоса **Проверки ссылок** на дашборде |
| Уведомления | Telegram: чаты, где включены «Проверки ссылок» (Уведомления → Telegram) |

## Что проверяется

- **Офферы** — все внешние офферы со ссылкой (не локальные и не в архиве). Ссылка открывается так, как её получает посетитель, с параметрами партнёрки и заполненными макросами; sub id — `orbitra-check`, чтобы клики можно было отличить от настоящих в статистике партнёрки.
- **Домены** — все трекинговые домены, по HTTPS, когда есть сертификат. Домен работает, когда его веб-сервер вообще отвечает: 404 — это настроенный ответ, мёртвый хост — нет.

## Как идёт проверка

Воркер запускается раз в минуту и проверяет то, что настало, — столько ссылок, сколько влезает в его бюджет времени; остальное ждёт следующей минуты.

1. Ссылка открывается без автоматического следования редиректам: каждый переход сначала проверяется на публичный адрес (сервер никогда не используется как дверь в собственную сеть), затем проходится. До пяти редиректов плюс переходы, которые делает сама страница (meta refresh, `location.href = …`).
2. Каждый переход записывается: URL, код ответа, время.
3. Вердикт:
    - **Сломано** — сайт отвечает 4xx/5xx, не отвечает вовремя, домен не резолвится, сертификат сломан, петля редиректов.
    - **Внимание** — ссылка теперь ведёт на другой домен; защита сайта (Cloudflare и подобные) не пустила проверку; переход с HTTPS на HTTP; очень медленный ответ.
    - **Работает** — конечная страница отвечает 2xx и ведёт туда, куда ожидается.

### Сначала подтверждение

Одна неудачная проверка — ещё не поломка: через две минуты ссылка проверяется ещё раз, и только вторая неудача помечает её **Сломано** и отправляет уведомление. Для восстановления достаточно одной удачной.

### Ожидаемый домен

Для офферов запоминается домен, на который ссылка привела при первой успешной проверке. Если позже ссылка ведёт на другой домен (оффер подменили, трафик уходит на заглушку), статус становится **Внимание**. Можно самому перечислить допустимые домены для ссылки или не сверять домен совсем.

### Прокси

По желанию. Без прокси запрос идёт с адреса самого сервера. Прокси из страны оффера заставит гео-оффер ответить так, как он отвечает посетителю.

Прокси добавляются в **Интеграции → Проверки ссылок** одной строкой: `socks5://user:pass@host:port` (также `http`, `https`, `socks4`). Новый прокси проверяется сразу, затем каждые десять минут. Адрес прокси должен быть публичным: прокси на самом сервере или в его сети панель не принимает.

Ссылка, которая проверяется через неработающий прокси, не считается сломанной. Вина — прокси: он получает одно своё сообщение, а ссылки за ним не обвиняются.

## Настройки

**Общие** (Интеграции → Проверки ссылок):

- **Проверять офферы / проверять домены** — что попадает в проверки.
- **Как часто проверять** — интервал по умолчанию для всех ссылок, от 5 минут до 7 дней.
- **User-Agent** — тем, чем проверка представляется; по умолчанию Chrome на Windows.
- **Ставить оффер на паузу, когда он окончательно сломан** — оффер будет поставлен на паузу один раз; включать его обратно — ваше решение.

**Для отдельной ссылки** (шестерёнка в списке): свой интервал, прокси, User-Agent и ожидаемый домен либо отключение проверки для этой ссылки.

**Проверить сейчас** (только для администраторов) ставит ссылку в ближайший запуск воркера. Не больше 100 за десять минут, чтобы зажатая кнопка не превратилась в поток кликов.

## Уведомления

Telegram, при смене статуса — никогда на каждую неудачную проверку:

- 🔴 ссылка не открывается, с причиной простыми словами и цепочкой хостов;
- 🟡 ссылка требует внимания: другой домен, защита сайта;
- 🟢 ссылка снова работает, и сколько она не открывалась;
- ⚠️ прокси не отвечает — одно сообщение на прокси, а не на каждую ссылку — и когда он вернулся.

Если в одном запуске ломается много ссылок сразу (упала сеть), уходит одна сводка вместо потока сообщений. URL ссылки в сообщения не включается намеренно: в групповом чате он стал бы публичным.

## Воркер

`link_checks_cron.php`, раз в минуту:

```
* * * * * php /var/www/orbitra/link_checks_cron.php >> /var/www/orbitra/var/logs/link_checks.log 2>&1
```

Свежая установка добавляет его вместе с остальными. Существующая получает строку в тот момент, когда функция включается и панель может управлять crontab; иначе карточка в Интеграциях показывает строку, которую нужно добавить вручную. Пока воркер не запущен и функция включена, панель говорит об этом в двух местах: в карточке Интеграций и в баннере фоновых воркеров. Пока функция выключена, воркер ничего не делает.

Если crontab ведётся вне панели, задайте в окружении `ORBITRA_CRON_SELF_HEAL=0`.

## API и MCP

Действия: `link_checks_summary`, `link_checks_list` и `link_checks_log` доступны каждому вошедшему пользователю; `link_check_now`, `link_checks_settings`, `save_link_checks_settings`, `save_link_check`, `check_proxies`, `save_check_proxy`, `delete_check_proxy` и `test_check_proxy` — только администраторам.

Инструменты MCP: `orbitra_link_checks_summary`, `orbitra_link_checks_list`, `orbitra_link_check_now`.

История проверок хранится 30 дней.
