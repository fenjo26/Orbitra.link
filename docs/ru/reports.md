# Отчёты, логи и метрики

## Часовой пояс и период

Все отчёты, графики и логи показывают время в одном поясе: выбранном в календаре периода, а если там ничего не выбрано — в поясе профиля. Список — около 350 зон по регионам, пояс профиля закреплён сверху. Первый день недели в календаре берётся из профиля. В таблицах при наведении на время видно UTC.

## Дашборд

- **Карточки и график** — визиты, клики, конверсии, доход, расход, прибыль за период. Набор карточек и метрика графика настраиваются в настройках дашборда.
- **Блоки «Кампании / Офферы / Лендинги / Источники / Страны»** — топ-10. Блок **«Страны»** стоит под остальными на всю ширину и включается в настройках дашборда. Он следует периоду и фильтру по кампании на дашборде; уникальные клики считаются по всем кампаниям, а при фильтре по одной кампании — по ней. Клик по заголовку колонки сортирует по любой колонке на экране, причём сортируется весь список до отбора топа. Сортировка запоминается для каждого блока. Клик по строке открывает настройки этой сущности: кампания — сразу в много-вкладочном редакторе, оффер, лендинг или источник — на своей странице с уже открытым редактором (PWA-лендинг — в собственном конструкторе); read-only пользователь попадает просто на страницу списка.
- **Колонки и пустые строки таблиц топ-10** — выбираются в настройках дашборда. По умолчанию включены клики, уникальные клики и конверсии; расход, доход и прибыль добавляются галочкой (пользователь без права на финансы их не видит). Прибыль подсвечивается зелёным или красным. Строки без кликов, конверсий и денег за период по умолчанию скрыты — заголовок блока считает, сколько их («Скрыто пустых: 1»); выключатель там же в настройках. Если выбранных колонок больше, чем влезает в карточку, таблица прокручивается вбок внутри неё.
- **Последние клики** — по умолчанию ID события, дата и время, кампания, ОС (логотип), браузер (логотип), IP, направление. Шестерёнка открывает выбор колонок (доступны ещё гео, тип устройства, сырой User-Agent, домен). Колонки перетаскиваются за ручку и меняют ширину, двойной клик по краю сбрасывает ширину.
- Если не установлена гео-база или установлен только Sypex Geo, сверху висит баннер с предложением подключить базу.

## Список кампаний

Колонки выбираются в настройщике отчёта; есть готовые пресеты (например, «Трафик», «Лендинг → Оффер»). Колонки перетаскиваются и меняют ширину; ID, статус и название закреплены слева и не уезжают при прокрутке широкой таблицы. На телефоне строки превращаются в карточки, набор метрик в карточке выбирается отдельно.

Кнопка лога кликов в строке кампании открывает полный лог трафика с фильтром по этой кампании.

**Сравнить** (рядом с выбором дат) добавляет под каждым числом изменение относительно такого же по длине предыдущего периода — в % для количеств и денег, в процентных пунктах для долей (ROI, CR…). Зелёный — лучше: для расхода и цены за единицу зелёным считается снижение. Строка «Итого» тоже сравнивается; выбор запоминается.

## Отчёт по кампании

Конструктор: группировка по одному или нескольким измерениям, фильтры, набор метрик, экспорт в CSV.

Отчёт открывается из пункта **Отчёты** главного меню — по всем кампаниям или по одной, выбранной рядом с вкладками, — а также кнопкой отчёта на странице кампаний и в редакторе кампании. Вторая вкладка той же страницы — журнал конверсий.

Клик по заголовку столбца сортирует, повторный меняет порядок на обратный. Строки сортируются внутри своего уровня группировки, поэтому дочерняя строка не уезжает от родительской. Числа начинают с наибольшего, названия с первой буквы алфавита. Пустые ячейки (прочерк) в обоих направлениях идут в конце. Сортировка запоминается, а первый клик по «Кликам» сразу даёт возрастание: отчёт и так открывается по кликам.

**Измерения:** кампания, домен, поток, лендинг, оффер, источник; страна, регион, город; тип устройства, ОС, браузер, язык; день, час; время до оффера (бакеты), время на лендинге (бакеты); первый и последний экран PWA; ID кампании / группы объявлений / объявления, ключевое слово, ID креатива, внешний ID, `sub_id_1` … `sub_id_5`; названия кампании, adset и объявления; UTM-площадка; ISP, ASN, мобильный оператор и тип подключения; вариант попапа (дизайн × текст).

**Атрибуция по домену:** измерение «Домен» группирует трафик по историческому хосту из `clicks.domain` на момент клика (в нижнем регистре), а не по текущему домену кампании. При ротации доменов прошлые клики и конверсии остаются за тем доменом, через который они пришли, а старые записи без сохранённого домена попадают в `Unknown`. Как и `Город`, `ISP`, `ASN` и `sub_id_*`, группировка по домену работает по сырым кликам (в пределах `stats_raw_retention_days`); при выходе периода за границу freeze отчёт откатывается на сырые данные и показывает плашку с датой доступности.

**Фильтры:** для всех измерений отчёта доступны операторы `=`, `!=`, `содержит`, `не содержит`, `в списке (a, b)` и `не в списке` (значения через запятую или с новой строки). Активные фильтры отображаются чипами в тулбаре отчёта с удалением в один клик.

Потоки, удалённые до версии со стабильными ID, показываются как «Удалённый поток #N», потоки без имени — «Поток без названия».

## Тренды и когорты

**Тренды** — графики метрик по дням, неделям, месяцам, часам или дню недели с фильтрами по кампании, офферу, источнику и параметрам. Мультивыбор кампаний и офферов. **Когорты** — кампании группируются по месяцу или кварталу запуска, и видно, как каждая когорта ведёт себя по месяцам жизни (M0, M1…).

## Логи

**⚙ → Логи**, вкладки: трафик, постбеки, S2S, системный, аудит, записи сессий.

### Журнал конверсий

**Отчёты → Конверсии** (также **⚙ → Конверсии**). Поиск по subid, tid или IP; фильтры по статусу, гео, кампании, офферу и сайту — лендингу, через который пришёл клик, — и по периоду. Они сужают друг друга. В таблице: ID клика, статус, выплата, кампания, оффер, гео, сайт, IP и дата; экспорт в CSV содержит то же. Фильтр по гео предлагает только страны, в которых есть конверсии в рамках доступа пользователя к кампаниям. Если журнал открыт из редактора кампании, кампания зафиксирована.

На вкладке **«Записи сессий»** — записи визитов с фильтрами, сортировкой, страницами и массовым удалением; подробно — [Записи сессий и карта кликов](session-recordings.md).

### Лог трафика

- **Колонки:** базовые плюс любой параметр клика отдельной колонкой (`ad_id`, `campaign_id`, `sub_id_N`, `ttclid`…). Подсказки берутся из параметров, реально встречавшихся в кликах за 14 дней. Выбор и порядок колонок запоминаются в браузере.
- **Фильтры:** кампания, поток, маршрут и причина клоаки, период; по параметрам — равно / не равно / в списке / не в списке / пусто / не пусто, до 5 условий. «Пусто» отвечает на вопрос «какие клики пришли без этого параметра».
- **Подгрузка:** «Показать ещё» без потолка в 100 строк. Пагинация по курсору, поэтому новые клики не сдвигают страницу.
- **CSV:** те же фильтры и видимые колонки, до 100 000 строк, разделитель `;`, UTF-8 с BOM (Excel открывает по колонкам). Ячейки, начинающиеся с `= + - @`, экранируются.
- **Колонка «Sub ID 1»** — входящий параметр `sub_id_1`, а не ID клика. ID клика, который уходит в сеть, — это ID события.
- **ОС и браузер** — логотип и версия; встроенные браузеры приложений (Facebook, Instagram, TikTok…) и имена ботов распознаются.

### Карточка клика

Открывается по ID клика в дашборде, логах и журнале постбеков:

- устройство: ОС и браузер с версиями, марка и модель, встроенный браузер приложения, имя бота — разбирается из сохранённого User-Agent при открытии, поэтому работает и для старых кликов;
- поток, который взял клик («EU (обычный)»), уникальность (кампания / поток / глобально), флаг прокси, ISP / ASN;
- **Направление** — реальный URL редиректа с параметрами сети и ID клика, либо действие потока (404, текст, белая страница, «в кампанию #N»);
- домен, на который пришёл клик;
- время в поясе панели с названием пояса и отдельная строка UTC; время показа лендинга, перехода на оффер и время до оффера;
- время на лендинге и глубина прокрутки;
- кнопка **«Запись сессии»**, если лендинг записал этот визит ([Записи сессий](session-recordings.md));
- все параметры клика, ID рекламных сетей первыми;
- вердикт и причины клоаки — только если клик судила клоака;
- итог **проверки браузера** и её признаки (видеокарта, платформа, часовой пояс), если клик проверялся ([Проверка браузера](browser-check.md)).

## Как считаются метрики

| Метрика | Определение |
|---|---|
| **Клики** | Каждый заход на ссылку кампании, каким бы потоком он ни был обслужен (как в Keitaro, с версии 1.8.5). Хиты safe page выпадают, если включено «Исключить клики Safe Page из отчетов» |
| **Визиты** | Те же хиты, что и клики, — отдельная колонка как знаменатель CPV/EPV |
| **Переходы на оффер, LP clicks** | Воронка оффера: прямые переходы на оффер плюс показы лендинга, с которых посетитель реально ушёл на оффер |
| **Уникальные** | Отдельно по кампании, потоку и глобально |
| **CPC, CR, EPC** | Делятся на клики |
| **CPV, EPV** | Делятся на визиты — теперь равны CPC и EPC, раз каждый визит это клик |
| **ROI** | Прибыль ÷ расход |
| **Маржа** | Прибыль ÷ доход |
| **Реальные клики LP / на оффер, Real LP CTR** | Только клики с зафиксированным переходом лендинг → оффер |
| **Время на лендинге, отказы LP, глубина прокрутки** | По таймеру на странице лендинга. Считается только видимое время; знаменатель — визиты, где таймер отработал. Визиты без таймера (чужой домен без скрипта, боты без JS) — «Неизвестно», а не ноль |
| **Возможные боты** | Визиты с работавшим таймером лендинга, где не было ни одного движения мыши или касания. Это подсказка присмотреться к источнику, а не исключение из статистики |
| **Подтверждённые** доход / профит / ROI | Только конверсии подтверждённых типов |
| **Попап: показы / CTR / клики / закрытия / конверсии** | См. [Конверсионные попапы](conversion-popups.md) |
| **Просмотры экранов PWA** | См. [PWA Funnel](pwa-funnel.md) |

Свои формулы — **Настройки → Пользовательские метрики**.

Если в кампании включено «Исключить клики Safe Page из отчётов», белые хиты уходят из кликов, визитов и всего, что от них считается ([Клоакинг](cloaking.md#запись-и-отчёты)).

## Состояние системы

**⚙ → Состояние** — диск, CPU, RAM, размер базы и рекомендации. На хостингах, которые прячут `/proc`, RAM показывается как N/A.
