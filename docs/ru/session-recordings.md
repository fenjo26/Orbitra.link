# Записи сессий и карта кликов

Смотрите, как посетитель вёл себя на вашем лендинге: движение мыши, скролл, клики и тапы, всё это воспроизводится как видео. Это похоже на Яндекс Вебвизор или Microsoft Clarity, только записи хранятся на вашем сервере. Для каждого лендинга также есть **карта кликов** и **карта скролла**.

С версии 1.8.3 записи работают и для **целых сайтов**, а не только лендингов: органический сайт (SEO-трафик, ваши сервисные страницы) со скриптом трекера на каждой странице записывается по всем страницам — один визит это одна запись, с переходами в плеере и картой кликов по каждой странице. См. [«Запись целого сайта»](#запись-целого-сайта-органический-трафик) ниже.

## Как включить

1. Откройте лендинг → вкладка **«Запись сессий»**.
2. Поставьте галочку **«Записывать сессии на этом лендинге»**.
3. Выберите, **какую часть посетителей записывать**: 5 / 10 / 25 / 50 / 100 %. Посетители выбираются случайно, но для каждого клика выбор постоянный: один и тот же клик либо записывается всегда, либо никогда.
4. Выберите, **сколько времени записывать**: «пока не выключу», 1 час, 24 часа, 3 дня или 7 дней. Когда время выйдет, запись остановится сама, а уже сделанные записи останутся.
5. Нажмите обычную кнопку **«Сохранить»** лендинга.

На вкладке видна оценка по реальному трафику лендинга за последние 24 часа, например: «около 120 записей в день, примерно 18 MB».

Ботов и посетителей safe-страницы трекер **не записывает никогда**. Сервер решает это ещё до отправки страницы, поэтому таким посетителям не отдаётся даже скрипт записи.

## Запись целого сайта (органический трафик)

Если сайт — не лендинг, а сервис на SEO, прямом и соцтрафике, запись включается на уровне **кампании**:

1. Поставьте `tracking.js` на **каждую страницу** сайта между `<head>` и `</head>` (сниппет — на вкладке **Tracking** кампании). Для этого используйте именно `tracking.js` — `kclient.js` и `kclient.php` не умеют ни склейку мультистраничных визитов, ни API согласия.
2. Откройте кампания → вкладка **Интеграции** → карточка **«Записи сессий»**.
3. Настройки те же, что у лендинга: доля посетителей (для живого сайта обычно хватает 5–10 % — каждая страница визита занимает место), срок записи и живая оценка по реальному трафику кампании.
4. Отметьте **«Многостраничный сайт: один клик на визит»**, если нужна ещё и склейка визитов — см. следующий раздел.

Визит записывается по всем страницам: в плеере видны переходы, в списке — сколько страниц открыл посетитель и какие были первая и последняя, у карты кликов появляется **выбор страницы** (своя карта на каждую), а в списке записей можно фильтровать по кампании, источнику трафика (Google / Bing / Яндекс / соцсети / прямой заход), подстроке страницы и «многостраничные».

Переключатель кампании действует и на клики, пришедшие на лендинг без собственных настроек записи, но лендинг, который вы хоть раз настраивали для записи, полностью рулит своими кликами: его выключенное состояние имеет приоритет.

## Один клик на визит

Без этой настройки каждая страница сайта регистрирует в кампании свой клик — как было всегда. С включённой **«Один клик на визит»** посетитель, переходящий по страницам сайта, — это **один** клик: статистика перестаёт раздуваться просмотрами страниц, а запись склеивается в одну сессию.

У склейки есть защита, чтобы платный клик никогда не поглощался запомненным:

- трекер склеивает, только когда посетитель пришёл **с этого же сайта** (внутренний переход) и с прошлой страницы прошло меньше **30 минут**;
- запрос с **новыми или изменившимися рекламными метками** (`fbclid`, `gclid`, `ttclid`, `msclkid`, `utm_*`, `sub_id_N`, …) — это новый вход в кампанию, даже внутри этих 30 минут: второй рекламный клик получает свой клик, свои параметры и свою атрибуцию в CAPI. Сайт, который протаскивает **те же** метки по внутренним ссылкам, склеивается как обычно;
- галочка **выключена по умолчанию**: обновление само не меняет ничью статистику, пока вы не включите её сами.

## Согласие на cookies (сайты в ЕС)

Посетителям из ЕС запись сессий требует согласия. Отметьте **«Записывать только после согласия на cookies»** в карточке кампании — пока посетитель не согласился, **не пишется ничего, даже клики для карты**. Рекордер запускается из баннера cookies одним вызовом:

```js
window.OrbitraReplay && OrbitraReplay.consent();
```

Защита `window.OrbitraReplay && …` важна: заглушка `OrbitraReplay` живёт в `tracking.js`, и ваш баннер может сработать раньше, чем он загрузится. Два равнозначных варианта:

- менеджер согласия может сам положить в localStorage ключ `orbitra_replay_consent` со значением `1` — рекордер опрашивает его и стартует прямо на текущей странице, а не со следующей;
- `OrbitraReplay.revoke()` отзывает согласие и останавливает запись на лету; вызывайте его, когда посетитель отказался.

Данное согласие запоминается, поэтому следующие страницы визита записываются с самого начала. Чистить его при отказе посетителя — работа вашего баннера. Режим согласия управляет тем, что пишется на диск; маскирование полей из раздела [«Приватность»](#приватность) работает всегда.

## Где работает запись

| Где | Как |
|---|---|
| Лендинг, загруженный в Orbitra (ZIP или редактор), или action-лендинг «Показать HTML» | Автоматически |
| Внешний лендинг с `tracking.js` / `kclient.js` | Автоматически: скрипт подгружает `/replay.js`, если ответ Click API говорит, что этот клик записывается |
| Внешний лендинг с `kclient.php` | Автоматически: актуальный `kclient.php` сам выводит тег записи в конце страницы. Можно поставить его и вручную: `<?php echo $client->replayScript(); ?>` |
| Целый сайт с `tracking.js` на каждой странице | Автоматически (1.8.3): переключатель кампании в разделе Интеграции покрывает все страницы визита |
| Кампания с прямым редиректом на оффер | Невозможно: записывать нечего, страницы нет |

Склейка мультистраничных визитов (продолжение по `_subid`) и заглушка согласия есть только в `tracking.js`; `kclient.js` и `kclient.php` записывают свою единственную страницу, но визиты не склеивают и `OrbitraReplay` не предоставляют.

## Просмотр записей

**⚙ → Логи → Записи сессий.** Фильтры: лендинг, кампания, период, устройство (компьютер / телефон), источник трафика (Google / Bing / Яндекс / соцсети / прямой заход — по рефереру), подстрока страницы (ищет по первой или последней странице визита), «многостраничные», минимальная длительность, «перешли на оффер», «с конверсией», «с яростными кликами». В каждой строке: время, страна и устройство, лендинг и кампания, длительность, клики (значок 🔥 для яростных кликов), глубина скролла, итог (конверсия / на оффер / ушёл) и размер записи; у многостраничных визитов — бейдж «N стр.» с путём первая → последняя.

Список сортируется по любой колонке (повторный клик меняет направление) и разбит на страницы, размер страницы выбирается внизу.

**Удаление.** Отметьте записи галочками или поставьте галочку в заголовке, чтобы выбрать всю страницу. Появится панель с кнопками «Удалить (N)» и «Снять выделение». Если страниц несколько, там же будет «Выбрать все записи по этим фильтрам (N)»: она выбирает сразу все записи под текущими фильтрами на всех страницах. Например, «удалить все мобильные отказы короче 5 секунд с лендинга X» делается так: выставить фильтры → галочка в заголовке → «Выбрать все…» → «Удалить». У каждой строки также есть своя корзина, а в панели хранилища есть «Удалить записи этого лендинга» и «Удалить все записи».

В плеере есть пуск и пауза, шкала времени с красными отметками кликов, скорость от 1× до 8× и **«Пропускать бездействие»**: плеер перескакивает паузы, в которых ничего не происходило. В карточке клика в логе трафика появляется кнопка **«Запись сессии»**, если этот клик был записан.

**Яростный клик**: три клика в одно место быстрее чем за 0,7 с. Обычно это значит, что кнопка или элемент не реагирует, и это стоит исправить.

## Карта кликов и карта скролла

Карта открывается с вкладки записи в лендинге, из карточки записи в кампании или кнопкой **«Карта кликов»** в списке записей, когда выбран лендинг или кампания.

- **Клики**: куда нажимают, от синего (редко) до красного (часто). Красные кольца отмечают яростные клики. Для компьютера и телефона карты отдельные, потому что вёрстка у них разная.
- **Скролл**: страница разбита на 10 полос с подписями «X % дошли до Y %». Данные берутся из таймера времени на странице, поэтому здесь учтены **все посетители с замером**, а не только записанные.
- **Выбор страницы** (многостраничные сайты): у каждой страницы сайта своя карта кликов — выберите путь, и точки с фоном перестроятся на эту страницу. Без этого страницы слились бы в одну бессмысленную систему координат.

Фон карты строится из последней записи с таким же типом устройства (для выбранной страницы — из её кадра внутри записи). Запросов к живому сайту нет, клики не создаются.

## На что смотреть

Несколько сценариев, где записи окупаются в ежедневной работе:

- **Лендинг не конвертит.** Выберите лендинг, поставьте «Длительность ≥ 15 s», галочку «Перешли на оффер» не ставьте, и посмотрите 5–10 визитов. Люди, которые читали и всё равно не нажали, обычно показывают причину: на телефоне кнопка ниже первого экрана, таймер или попап перекрывает кнопку, форма выглядит сломанной.
- **Яростные клики.** Поставьте «С яростными кликами». Скопление в одном месте почти всегда означает элемент, который выглядит кликабельным, но не работает (картинка видео, нарисованная кнопка, пустой якорь). На карте кликов то же видно сразу, красными кольцами.
- **Телефон против компьютера.** Откройте карту для обоих. Если на карте скролла телефонные посетители не доходят до блока заказа, сократите страницу или повторите кнопку выше.
- **Качество трафика.** Живые люди ведут курсор дугами, останавливаются и скроллят неровно. Поток записей без движения мыши, с мгновенным идеальным скроллом или кликами через секунду после загрузки говорит о слабом или ботовом трафике с этого источника или площадки, даже если он прошёл фильтры клоаки.
- **До и после.** Поменяли лендинг — удалите его старые записи (фильтр по лендингу → галочка в заголовке → «Выбрать все…» → «Удалить») и сравните новую карту кликов со старой.

Обычно хватает записи 10 % посетителей в течение суток-двух, чтобы увидеть картину. Держать 100 % постоянно не нужно.

## Лимиты хранения

Лимиты общие для всего, что пишет: лендингов и кампаний. Они видны на вкладке записи в лендинге, в карточке кампании и под кнопкой размера в списке записей:

- **Хранить записи** 1 / 3 / 7 / 14 / 30 дней. Старые записи удаляются автоматически.
- **Максимум места на диске**: от 256 MB до 20 GB. Когда место заканчивается, **самые старые записи удаляются**, а новые записываются на их место.

Встроенная защита, которую нельзя отключить:

- одна запись ограничена 30 минутами и 5 MB;
- если на диске сервера меньше 1 GB свободного места, новые записи не начинаются;
- записи, в которые так и не пришли данные, удаляются через 2 часа.

Обычная запись занимает 50–300 KB: это структура страницы и её изменения, а не видео. В карточке хранилища показан средний размер ваших реальных записей и сколько их поместится в выбранный лимит.

Очистка запускается не чаще раза в минуту: от входящих записей и при открытии списка. **Добавлять cron не нужно**, выполнять команды на сервере после обновления тоже не нужно.

## Приватность

- **Все поля форм маскируются ещё в браузере посетителя.** Введённые данные (телефон, имя, пароль) не покидают устройство, в записи видны звёздочки.
- Чтобы полностью скрыть блок, добавьте ему класс `orbitra-no-record`: в записи на его месте будет пустой прямоугольник. Класс `orbitra-mask` маскирует текст блока.
- Записи лежат в `var/replays/` на вашем сервере, а конфиг nginx никогда не отдаёт эту папку наружу. Читать записи можно только через панель, пользователям с доступом к лендингам.
- Если вы записываете посетителей из ЕС, включите [режим согласия](#согласие-на-cookies-сайты-в-ес) или упомяните запись сессий в политике конфиденциальности сайта.

## Если что-то не так

**На вкладке написано «Запись включена», а список пустой.**
- Проверьте, что визиты действительно попадают на **этот лендинг**: поток должен вести на него, а посетители не должны быть ботами или посетителями safe-страницы (их не записываем никогда).
- При маленькой доле (5 %) и небольшом трафике первая запись может появиться не сразу. Для быстрой проверки поставьте 100 % и откройте ссылку кампании с телефона.
- Проверьте, не вышел ли срок записи: если вышел, на вкладке лендинга написано «Запись остановилась…».
- Внешний лендинг: на странице должен стоять `tracking.js`, `kclient.js` или актуальный `kclient.php`. Старая копия `kclient.php` о записях не знает, скачайте её заново на вкладке **Tracking** кампании (кнопка скачивания kclient.php).

**«Запись слишком короткая для просмотра».** Посетитель ушёл раньше, чем отправился первый снимок страницы (обычно меньше секунды). Для части отказов это нормально.

**Многостраничные визиты всё ещё отдельные клики.** Для склейки «один клик на визит» нужно всё сразу: галочка включена в карточке кампании, на каждой странице стоит именно `tracking.js` (не kclient), и посетитель реально ходит по сайту. Вход с рекламы, из закладок или с другого сайта намеренно создаёт новый клик — платные клики не склеиваются никогда. Проверьте и окно в 30 минут: после долгой паузы следующая страница начнёт новый клик.

**В записи нет стилей или картинок.** Картинки и шрифты плеер подгружает по адресам самого лендинга. Если файлы лендинга удалили или заменили после визита, старые записи показать их не смогут.

**Новые записи перестали появляться.** Посмотрите на карточку хранилища: если на диске сервера меньше 1 GB свободного места, запись приостанавливается, пока не освободите место или не уменьшите лимит.

**У записи метка LIVE.** Посетитель ещё на странице. Пачки приходят каждые несколько секунд, поэтому запись растёт, пока он не уйдёт (максимум 30 минут).

## Технические детали

- Запись: [rrweb](https://github.com/rrweb-io/rrweb) (`@rrweb/record`), собран в `/replay.js` (около 25 KB в gzip). Скрипт грузится с `defer` и только для записываемых кликов, пачки событий сжимаются gzip прямо в браузере.
- Приём: `POST /pixel.gif?action=rr`. Пачка принимается только для клика, который сервер сам «взвёл», и только с его HMAC-подписью.
- Хранение: по одному файлу `.ndjson.gz` на запись, плюс таблицы `session_replays`, `replay_clicks` (точки карты кликов, хранятся 30 дней) и `replay_landing_settings` из миграции 76.
- Органические сайты (1.8.3, миграция 78): таблица `replay_campaign_settings` (переключатель кампании, режим согласия, «один клик на визит»), колонки `entry_url` / `pages` для мультистраничных сессий, точки карты с указанием страницы и продолжение визита в Click API v3 — `tracking.js` шлёт `?_subid=` на внутренние страницы визита, сервер сверяет рекламные метки с параметрами запомненного клика. Код: ветка продолжения в `core/click_api.php`, `core/SessionReplay.php`.
- Код: `frontend/replay/recorder.js` (пересобрать: `npm run build:replay`), `frontend/src/components/replay/`, `tracking.js`.
