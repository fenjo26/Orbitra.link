# Внешние PWA и Telegram-каналы

Два способа расширить воронку за пределы собственного конструктора Orbitra: сторонние PWA-сервисы как цели потока и Telegram-каналы как офферы с атрибуцией подписчиков.

## Внешние PWA-конструкторы

Сторонний сервис (PWA.Group, TSL.app или любой другой) может быть целью потока точно как лендинг:

1. **Создайте конструктор** — Администрирование → Внешние PWA. Выберите сервис из каталога (`data/external_pwa_services.json`: шаблон URL редиректа, шаблон постбэка, маппинг статусов) или заполните свой — ваши значения побеждают каталог. **Каталожные записи — шаблоны: сверьте каждый параметр с актуальной документацией сервиса перед боем.**
2. **Настройте возврат**: в настройках сервиса укажите адрес возврата после установки
   `https://<домен-трекера>/eflow/<алиас-кампании>?subid={subid}&eid={eid}`
   (страница показывает точную форму для копирования).
3. **Добавьте в поток** — в блоке лендингов редактора кампании «Добавить внешний PWA». Внешние конструкторы делят тот же взвешенный пул с лендингами — веса дают A/B «свой PWA против чужого» в одной воронке.

Что происходит на трафике: клик уходит в сервис с `subid` = click id (`clicks.external_pwa_id` помнит, куда). Когда посетитель возвращается на `/eflow/<алиас>`, трекер ставит установку (`external_install_at`), сохраняет `eid` сервиса (живёт 7 дней) и продолжает на оффер по выбору кампании — ровно как «свой» PWA после установки.

Конверсии этих кликов уходят постбэком в сервис через ту же надёжную s2s-очередь, что и партнёрские: `subid` + `eid` + статусное слово сервиса (маппинг по сервису) + выплата. В отчётах кампании появляется колонка внешних установок.

## Telegram-каналы как офферы

Оффер «Telegram-канал» ведёт посетителей из рекламы в канал через **бота воронки** и засчитывает вступление как конверсию. Боты воронки **отделены от админского бота** (Интеграции → Telegram): админский бот отвечает только подключённым вами чатам и читает статистику, поэтому посторонние из рекламы до него доходить не должны. Токен админского бота как бот воронки панель не принимает.

Настройка:

1. Создайте нового бота в @BotFather и добавьте его токен в **Админка → Telegram-боты воронки**.
2. Добавьте этого бота в свой канал администратором с правом **«Пригласительные ссылки»**. Канал сам появится в карточке бота (или добавьте его там по `@имени`, `t.me/…` или `-100…`).
3. Создайте оффер с типом **Telegram**, выберите бота и канал, задайте окно вступления (1–7 дней) и, при желании, приветствие.
4. Поставьте оффер в поток кампании и лейте трафик по ссылке кампании. Прямую ссылку на канал не раздавайте — такие вступления не атрибутируются.

Воронка:

1. Клик → `https://t.me/<бот воронки>?start=<subid>` — `/start` привязывает пользователя Telegram к клику (`tg_start`).
2. Бот отвечает приветствием и **инвайтом с заявкой** (`creates_join_request=true`, истекает вместе с окном оффера).
3. `chat_join_request` → бот одобряет только тех, кого сам пригласил в пределах окна, и пишет конверсию `tg_join` (с кампанией и оффером) на привязанный клик. Заявки остальных остаются модераторам канала.
4. Партнёрка, которая знает только подписчика, шлёт **обычный постбэк** с `tg_user_id` и `channel_id` вместо `subid`:
   `https://<домен>/<postback key>/postback?tg_user_id={tg_user_id}&channel_id=-100…&status=deposit&payout=50`
   — клик находится по последнему вступлению этого пользователя в канал за 30 дней. Точный URL показан на вкладке «Интеграция» редактора оффера.

Ботов воронки опрашивает `cli/tg_funnel_poll_cron.php` (раз в минуту, все боты параллельно, без вебхука — работает и без домена). `install.sh` ставит его в крон; если поллер не работает, страница ботов показывает строку для crontab.
