# Задача: эксперимент — две правки на тестовом трекере, потом повторный прогон генератором

Спасибо за DIAG.md, вывод подтвердился. Причина 4 fdatasync на клик: каждый запрос PHP-FPM открывает новое соединение с SQLite и закрывает его в конце. Когда закрывается последнее соединение, SQLite делает чекпоинт и **удаляет WAL-файл**. Следующий запрос создаёт WAL заново: fdatasync заголовка WAL, fdatasync каталога, fdatasync коммита, а на закрытии fdatasync чекпоинта. На диске с fdatasync ~8,5 мс это ~25–35 мс на клик.

Проверено в другом окружении на том же коде 1.9.4 (strace, 60 последовательных уникальных кликов):
- как сейчас: **4,00 fdatasync, 2 unlink, 2 ftruncate на клик**;
- с постоянным соединением PDO: **0,03 fdatasync на клик** (один чекпоинт на ~60 кликов), WAL-файл живёт постоянно.

Это тестовый сервер, Руслан разрешил временно изменить его для эксперимента. Каждое изменение сохрани как бэкап и опиши в `/root/loadtest/EXPERIMENT.md`.

## Изменение 1: постоянное соединение с SQLite (только для веб-запросов)

В `/var/www/orbitra/config.php` в массиве `$pdoOptions` (около строки 18–22) после `PDO::ATTR_TIMEOUT => 5` добавь:
```php
PDO::ATTR_PERSISTENT => (PHP_SAPI !== 'cli'),
```
Сразу после `$pdo = new PDO(...)` добавь защиту от транзакции, которую мог оставить упавший предыдущий запрос того же воркера:
```php
if (PHP_SAPI !== 'cli' && $pdo->inTransaction()) { $pdo->rollBack(); }
```
Бэкап: `cp config.php /root/loadtest/config.php.orig`. Проверки: `php -l config.php`, перезапуск php-fpm, смоук (302 и строка в clicks), панель открывается и логинится.

**Важно для `orbitra-lt-reset`:** при постоянных соединениях воркеры держат старый файл базы открытым. Скрипт уже останавливает php-fpm перед заменой файла, так что всё в порядке. Убедись в этом одним прогоном reset и смоуком после него.

Замер как в DIAG (п. 3 и п. 4): p50/p90/p99 200 последовательных новых посетителей и `strace -c` по воркерам: fdatasync/unlink на клик. Запиши до/после.

## Изменение 2: лимит соединений nginx

В `/etc/nginx/nginx.conf`: `worker_connections 768;` → `worker_connections 4096;`, а на верхнем уровне добавь `worker_rlimit_nofile 16384;`. `nginx -t`, `systemctl reload nginx`. Бэкап исходного файла в `/root/loadtest/nginx.conf.orig`.

`pm.max_children = 64` не трогай.

## После правок

`orbitra-lt-reset`, проверь loadavg < 0,5 и скажи Руслану одной строкой: «правки применены, замеры до/после такие-то, можно запускать генератор». Генератор повторит лестницы с теми же скриптами.

## Откат (по команде Руслана)

Вернуть `config.php.orig` и `nginx.conf.orig`, перезапустить php-fpm и nginx, `orbitra-lt-reset`, смоук.
