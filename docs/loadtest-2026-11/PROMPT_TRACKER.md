# Задача: подготовить сервер с Orbitra к нагрузочному тесту

Ты работаешь на чистом VPS (Ubuntu 24.04, 4 vCPU). Здесь будет стоять трекер Orbitra. Его будет нагружать второй сервер с k6. Тот сервер ведёт тест сам и ходит сюда по SSH. Твоя задача: поставить Orbitra так, как поставил бы обычный пользователь, подготовить тестовую кампанию и выдать генератору ограниченный доступ. **Сам тест ты не запускаешь и ничего не оптимизируешь.**

Методика повторяет тест CPA.RIP «Нагрузочное тестирование бесплатных self-hosted CPA-трекеров» (16.11.2026). Важно, чтобы трекер был в «коробочном» состоянии.

## Правила

- Никаких правок кода Orbitra, конфигов nginx/php-fpm/SQLite, sysctl, лимитов. Только то, что делает `install.sh`, и то, что пользователь делает в панели. Если что-то сломалось при установке, опиши и спроси, а не чини руками.
- Никаких других сервисов на этом сервере (кроме sshd и того, что ставит install.sh). Не ставь мониторинг-агенты, которые едят CPU.
- Всё, что сделал, записывай в `/root/loadtest/TRACKER_SETUP.md`: команды, версии, параметры кампании, всё нестандартное.

## Шаги

1. **Система.** `apt update && apt -y upgrade`, перезагрузка, если её просят. Запиши в отчёт: `lsb_release -a`, `nproc`, `lscpu | head -20`, `free -m`, `df -h /`.

2. **Установка Orbitra** — ровно как в README:
   ```
   wget -O orbitra-install.sh https://raw.githubusercontent.com/fenjo26/Orbitra.link/main/install.sh && bash orbitra-install.sh
   ```
   Если установщик предлагает выполнить `cli/server_setup.sh`, выполни его, так делает обычный пользователь. Запиши версию из `/var/www/orbitra/version.json`, а также версии `php -v`, `nginx -v`, `sqlite3 --version`.

3. **Панель.** Пройди мастер первого входа, создай админа. Пароль сохрани в `/root/loadtest/admin.txt` (chmod 600) и никому не показывай. Если панель предлагает поставить гео-базы в один клик, поставь всё, что ставится бесплатно и без ключей: обычный пользователь так и сделает. Запиши, какие базы встали.

4. **API-ключ.** В панели (Пользователи / профиль → API-ключи) создай ключ с правами записи. Сохрани его в `/root/loadtest/api_key.txt` (chmod 600).

5. **Оффер и кампания** (через панель или API, как удобнее):
   - Оффер `LT offer`, URL `https://offer.example/?cid={subid}`, тип редиректа по умолчанию.
   - Кампания `LoadTest` с alias `loadtest`, один обычный поток на этот оффер, режим «редирект». **Настройки уникальности не трогай**, оставь по умолчанию, и запиши, какие они.
   - Проверь: `curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" -A "Mozilla/5.0 test" "http://127.0.0.1/loadtest?sub1=smoke-1"` → `302 https://offer.example/?cid=<uuid>`. Затем `sqlite3 /var/www/orbitra/orbitra_db.sqlite "select id, json_extract(parameters_json,'$.sub1') from clicks order by rowid desc limit 1"` → строка с `smoke-1`, и `id` совпадает с cid из редиректа.
   - Проверь то же с внешнего адреса сервера: `http://<публичный IP>/loadtest?...` должен давать тот же 302.
   - Запиши `campaign_id`.

6. **Доверие X-Forwarded-For.** Генератор шлёт заголовок `X-Forwarded-For` с разными публичными IP, чтобы изображать разных посетителей. Проверь, что Orbitra берёт IP из него: сделай запрос с `-H "X-Forwarded-For: 85.74.12.9"` и посмотри `ip` новой строки в `clicks`. Если трекер берёт IP соединения, а не заголовок, **не меняй код**, просто запиши это: генератор подстроится.

7. **Снимок чистой базы для повторов.** Удали смоук-клики (`DELETE FROM clicks WHERE campaign_id = <id>`, плюс связанные таблицы, если есть внешние ключи), затем сделай снимок:
   ```
   sqlite3 /var/www/orbitra/orbitra_db.sqlite ".backup /root/loadtest/clean.sqlite"
   ```
   Напиши скрипт `/usr/local/bin/orbitra-lt-reset` (root:root, 0755), который возвращает базу к снимку:
   - `systemctl stop php*-fpm` (и всё, что держит базу: проверь `fuser`/`lsof`, крон spool временно пропусти через флаг или просто дождись);
   - копирует `clean.sqlite` поверх `orbitra_db.sqlite`, удаляет `-wal`/`-shm`, выставляет владельца и права как были;
   - очищает `var/spool/clicks.log`, если есть;
   - `systemctl start php*-fpm`, ждёт, пока `curl http://127.0.0.1/loadtest?sub1=reset-check` вернёт 302, затем удаляет этот проверочный клик;
   - печатает `RESET OK`.
   Проверь скрипт дважды.

8. **Доступ для генератора.** Создай пользователя `ltcheck` без пароля, вход только по ключу. Публичный ключ генератора тебе передаст Руслан. Разреши ключ только с IP генератора (`from="<IP>"` в `authorized_keys`). Права:
   - чтение базы: добавь `ltcheck` в группу, которая может читать `orbitra_db.sqlite` и `-wal`/`-shm`, **или** дай sudo только на `sqlite3 -readonly /var/www/orbitra/orbitra_db.sqlite *`. Выбери самый узкий вариант, который работает в WAL-режиме, и проверь его;
   - `sudo -n /usr/local/bin/orbitra-lt-reset` без пароля (только этот скрипт, через `/etc/sudoers.d/ltcheck`, проверка `visudo -c`);
   - чтение `/proc/stat`, `/proc/loadavg`, `/var/log/php*-fpm.log`, логов nginx и `var/logs/` Orbitra (для поиска ошибок).
   Проверь сам от имени `ltcheck`: запрос к базе, `sudo -n orbitra-lt-reset`, `cat /proc/stat`.

9. **Файрвол.** Если включён ufw: 80/tcp открыт для всех (или хотя бы для генератора), 22 открыт. Больше ничего не меняй.

## Что отдать Руслану

Короткий блок, который он перешлёт генератору:
```
TRACKER_IP=...
CAMPAIGN_ALIAS=loadtest
CAMPAIGN_ID=...
ORBITRA_VERSION=...
DB=/var/www/orbitra/orbitra_db.sqlite
SSH_USER=ltcheck
DB_READ_CMD=<точная команда чтения базы, которой пользуется ltcheck>
RESET_CMD=sudo -n /usr/local/bin/orbitra-lt-reset
XFF_TRUSTED=yes|no
UNIQUENESS=<метод и окно по умолчанию>
```
И сам файл `/root/loadtest/TRACKER_SETUP.md`.

После того как генератор закончит, **ничего не удаляй**, пока Руслан не скажет. Если в процессе теста тебя спросят про ошибки, читай логи и отвечай, но конфигурацию не меняй.
