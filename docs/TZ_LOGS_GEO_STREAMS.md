## Этап 1: логи (v1.5.14) ✅ сделано

Реализация отличается от плана в одном: вместо offset используется keyset-курсор (`next_cursor`), потому что offset на живом трафике дублирует строки между страницами.

**Бэкенд, `api.php` `case 'logs'`**
1. Ограничить `limit` диапазоном 1..500 (`max(1, min(500, …))`), `offset >= 0`.
2. Отдавать `has_more`: запрашивать `limit + 1` строк и обрезать. `COUNT(*)` по clicks не делать, на больших базах это дорого.
3. Трафик: добавить `cl.stream_id`, `s.name AS stream_name`, `s.type AS stream_type` (LEFT JOIN streams). Добавить фильтр `stream_id`.
4. Postbacks: убрать N+1 (запрос имени кампании в цикле) и заменить на LEFT JOIN campaigns.
5. Новое действие `logs_export` с теми же `type` и фильтрами плюс `date_from`/`date_to`. Стримить CSV (`fputcsv` в `php://output`) батчами по 1000 через keyset (`WHERE id < :last_id ORDER BY id DESC`), жёсткий потолок 100 000 строк. Заголовки `Content-Disposition: attachment`. Проверка прав та же, что у `logs`; финансовые поля по правилам finance_masking.

**Фронт, `LogsPage.jsx`**
6. Добавить кнопку «Загрузить ещё» (offset += 100, дописывать в конец). Показывать её, пока `has_more`. При смене вкладки или фильтров сбрасывать offset.
7. Добавить кнопку «Экспорт CSV»: ссылка на `logs_export` с текущими фильтрами и периодом (по умолчанию 7 дней).
8. На вкладку трафика добавить колонку «Поток» (имя и бейдж типа: перехват / обычный / замыкающий) и фильтр по потоку, когда выбрана кампания.
9. Заменить текст `logs.lastRecords` → «Показаны последние записи. Нажмите „Загрузить ещё“ или выгрузите CSV.» Новые ключи (`logs.loadMore`, `logs.export`, `logs.stream`, `logs.filterStream`) добавить во все 7 локалей и прогнать `npm run check:i18n`.

**Тесты**: `tests/logs_pagination_test.php` (clamp, has_more, offset без дублей), `tests/logs_export_test.php` (CSV-заголовки, фильтр кампании, потолок, маскирование финансов).

## Этап 2: гео из коробки (v1.5.15)

1. Вынести логику скачивания Sypex из `api.php` в `core/geo_databases.php` → `orbitraUpdateSypex(): array` (используют и API, и CLI).
2. Добавить `cli/geo_update.php`: обновляет Sypex всегда, а MaxMind и IP2Location, если в настройках сохранены ключи. Идемпотентный, пишет в `var/logs/geo_update.log`.
3. `install.sh`: после установки vendor один раз запустить `php cli/geo_update.php` от www-data. Если сеть недоступна, это не фатально, выводится NOTE. Добавить крон `# orbitra-geo` раз в месяц (по образцу `IPRANGES_CRON_MARKER`). Проверить на всех ОС через `cli/os_matrix.sh`.
4. Для существующих установок запускать `geo_update.php` при git-update (`core/git_update.php`), если ни одной гео-базы нет.
5. Предупреждение `admin.noGeoDb` вынести в общий компонент `GeoDbWarning`. Показывать его на дашборде и во вкладке «Потоки», когда у потока есть фильтр по стране/гео. В баннере кнопка «Установить Sypex одним кликом».
6. Тест: `tests/geo_databases_test.php`, кейс «нет баз → update ставит Sypex» (с фикстурным zip, без сети).

Риск: sypexgeo.net бывает недоступен или медленный. Нужен таймаут 30 с и нефатальная ошибка. Установка не должна падать из-за гео.
